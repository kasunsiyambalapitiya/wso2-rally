B10Report vehicle issue
Reached from the amber control in the app bar of any in-progress screen (B2–B8), so a crew never has to finish or abandon a task first. Crew flags a breakdown or device issue; an alert with live location reaches organizers (A1 ⚠ Alerts, A6 monitor).
Annotation · Micro app
The amber ⚠ control in the app bar opens B10 from every in-progress screen (B2–B8) — a breakdown does not wait for a crew to finish the task they are on, so the action is one tap from anywhere. It lives in the header beside SCORE / DONE (the AppBarStats component) rather than in each screen body, so it costs no layout space and never competes with the primary action. It is absent on B1, where no vehicle is bound yet and there is nothing to report against, and on B9, where the run is over and the score locked. No per-user login — the device binds to a vehicle + crew (screen B1) and holds a team token. Tasks share one screen shell whose body is chosen by task type. Sensor tasks use Geolocation, DeviceMotion, and camera/BarcodeDetector; BLE beacon tasks fall back to QR/geofence checkpoints on iOS Safari.
