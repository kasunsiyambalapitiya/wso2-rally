# Rally Web App (Organizer Portal) Implementation Plan — Plan 2 of 3

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the organizer web app for WSO2 Motor Rally 2027 — event setup, routes/geofences, task library, vehicles/crews, and the live monitor + pavilion leaderboard — talking to the Go backend (Plan 1) over REST + WebSocket.

**Architecture:** React 19 SPA mirroring `customer-portal/webapp` exactly: runtime `window.config`, Asgardeo auth, TanStack Query over a `fetch`-based authenticated client, `react-router` 7 with layout/guard routes, feature-based `src/features/*`, `@wso2/oxygen-ui` components, `react-leaflet` maps. Server state lives in Query; cross-cutting UI state in React Context. No zustand, no axios.

**Tech Stack:** React 19.2 + React Compiler · Vite 7 · TypeScript 5.9 (strict) · `@wso2/oxygen-ui` 0.6 · `@tanstack/react-query` 5 · `react-router` 7 · `@asgardeo/react` + `@asgardeo/react-router` · `react-leaflet` + `leaflet` · `vitest` + `@testing-library/react` · pnpm.

## Global Constraints

- **Mirror `customer-portal/webapp` conventions verbatim** (folder layout, config pattern, auth flow, query-hook naming) — this is the reference implementation. Diverge only where the domain differs.
- **Runtime config, not build-time.** `index.html` loads `/config.js` before the bundle → `window.config`. All keys prefixed `RALLY_` (e.g. `RALLY_BACKEND_BASE_URL`, `RALLY_ASGARDEO_BASE_URL`, `RALLY_ASGARDEO_CLIENT_ID`, `RALLY_MAP_TILE_URL`, `RALLY_LOG_LEVEL`, `RALLY_THEME`). `vite.config.ts` `envPrefix: ["RALLY_"]`, dev port 3000. `public/config.js` is gitignored; commit `public/config.js.example`.
- **Auth headers:** every request sends `Authorization: Bearer <idToken>` **and** `x-user-id-token: <idToken>` (via `useAuthApiClient`). On token-expiry, single-flight `signIn()` redirect.
- **Error body:** the backend returns `{"message": ...}`. `ApiError{status, statusText}` + `getApiErrorMessage()` parse it; surface via the error-banner context.
- **License header:** Apache-2.0 header (year 2026) on every `.ts`/`.tsx` file.
- **Query hooks:** name `useGetX`/`useSearchX`/`useCreateX`/`useUpdateX`/`useDeleteX`; `queryKey`s come from a central `ApiQueryKeys` in `constants/apiConstants.ts`.
- **Package manager pnpm**, Node 20+. ESLint flat config, no prettier (matches webapp).
- **TDD:** `vitest` + `@testing-library/react`; test-first every task. Mock the API client / Asgardeo — no live backend in unit tests.

```ts
// src/config/apiConfig.ts  (Apache header)
export function getApiConfig() {
  const url = window.config?.RALLY_BACKEND_BASE_URL;
  if (!url) throw new Error("Api Config Error: Missing RALLY_BACKEND_BASE_URL");
  return { backendBaseUrl: url.replace(/\/$/, "") };
}
```

```ts
// src/config/authConfig.ts  (Apache header)
export function getAuthConfig() {
  const c = window.config;
  if (!c?.RALLY_ASGARDEO_BASE_URL || !c?.RALLY_ASGARDEO_CLIENT_ID)
    throw new Error("Auth Config Error: Missing Asgardeo configuration");
  return {
    baseUrl: c.RALLY_ASGARDEO_BASE_URL,
    clientId: c.RALLY_ASGARDEO_CLIENT_ID,
    scopes: ["openid", "email", "groups", "profile"],
    afterSignInUrl: window.location.origin,
    afterSignOutUrl: window.location.origin,
  };
}
```
