# Rally Micro App (In-Car, Embedded in the Open Super App) Implementation Plan — Plan 3 of 4

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the in-car participant micro app for WSO2 Motor Rally 2027 — every phone in a car joins the same session: pick the vehicle, geofenced zero-facilitator start, the 15 config-driven tasks, live score/leaderboard sync, arrival + vouchers, and a vehicle-issue report — against the Go backend (Plan 1).

**Architecture:** React 19 SPA mirroring `customer-portal/microapp`, **embedded in the [WSO2 Open Super App](https://github.com/opensuperapp/opensuperapp)** exactly as that app is. It is a static build the super app downloads as a zip, extracts, and loads into a `react-native-webview` from a `file://` path. Identity comes from the super app over the native bridge (`window.nativebridge.requestToken()` → an Asgardeo access token minted for this app's `clientId`), which `POST /sessions/join` exchanges for the rally's team token. Retains every microapp convention: `axios` client with interceptors, `zustand` store, `HashRouter`, `formik`+`yup`, the `.dto.ts`/`.model.ts` split with `toX(dto)` mappers, services exporting TanStack `queryOptions`/`mutationOptions`, runtime `window.config`, MUI + Oxygen theme, prettier.

**Tech Stack:** React 19.2 · Vite 7 · TypeScript 5 · `@mui/material` 7 + `@wso2/oxygen-ui` · `@tanstack/react-query` 5 · `react-router-dom` 7 (`HashRouter`) · `axios` · `zustand` · `formik` + `yup` · `dayjs` · `react-leaflet` · `vite-tsconfig-paths` · `vitest` + `@testing-library/react` · prettier · npm. **No `vite-plugin-pwa`** (there is no install target inside the super app) and **no `@zxing/browser`** (QR comes from the native scanner).

## Global Constraints

- **Mirror `customer-portal/microapp`, including the embedding.** axios interceptor client, zustand store, `HashRouter`, dto/model split, services with TanStack options, MUI+Oxygen theme, prettier `printWidth 120`, `vite-tsconfig-paths`, **`utils/bridge.ts` + `services/auth.ts` over `window.nativebridge`**. The only rally-specific addition is `services/session.ts`, which trades the super app's token for a rally team token.
- **It runs from `file://` inside a `WebView`.** Therefore `base:"./"`, `HashRouter`, `./config.js` (relative), and **no service worker, no web manifest, no install prompt**. Absolute asset paths and `BrowserRouter` both break.
- **Runtime config, not build-time.** `index.html` loads `./config.js`; `public/config.js.example` is committed and `public/config.js` is gitignored:
  ```js
  window.config = {
    BACKEND_BASE_URL: "http://localhost:8080",
    ASGARDEO_BASE_URL: "", CLIENT_ID: "",
    SIGN_IN_REDIRECT_URL: "", SIGN_OUT_REDIRECT_URL: "",
    IS_MICROAPP: true,
  };
  ```
  `config/endpoints.ts` reads `window.config.BACKEND_BASE_URL` and **throws** if missing; `WS_URL` is derived `http→ws`. `IS_MICROAPP` selects the bridge token path over a browser OIDC sign-in, so the same build runs in a desktop browser during development.
- **Two tokens.** The super app's Asgardeo access token proves *who the crew member is*; `POST /sessions/join` exchanges it plus the chosen `vehicleId` for the rally **team token**, and every `/sessions/me/*` call carries that. The axios client sends `Authorization: Bearer <teamToken>` + `x-user-id-token: <teamToken>`; on 401 it clears the session store and routes to `#/` (re-join), never silently retries forever. Persist the team token in the super app's **secure store** (`requestSecureStorePersistence`), not `localStorage`.
- **Bridge calls are promise-wrapped one-way messages.** `nativebridge.requestX()` posts to the native side, which calls a global `resolveX`/`rejectX`. `utils/bridge.ts` owns that plumbing and must **time out** — a topic the host does not implement never answers at all.
- **Error body:** backend returns `{"message": ...}`; surface via a snackbar context; never swallow.
- **dto/model split:** wire shapes in `src/types/<domain>.dto.ts` (string dates, nullable), UI models in `src/types/<domain>.model.ts` (typed, `Date` via dayjs); services hold `toX(dto): Model` mappers.
- **License header:** Apache-2.0 (year 2026) on every `.ts`/`.tsx`.
- **Sensor reality inside the WebView** (this replaces the old "iOS Safari" note):
  - **QR/barcode → the native scanner.** `nativebridge.requestQr()`. `getUserMedia` is blocked from a `file://` origin, so there is no web camera path and no `@zxing/browser`. Manual code entry stays as the fallback.
  - **DeviceMotion → still web**, still needs a gesture-triggered `DeviceMotionEvent.requestPermission()` on iOS.
  - **Geolocation → blocked until the super app changes.** See the prerequisites below.
  - **Screen wake → the host's problem.** `navigator.wakeLock` is not reliable in this WebView; ask the super-app team to keep the screen awake for a `fullscreen` micro app.
  - BLE is never used: Task 8 is QR or geofence.
- **TDD:** `vitest` + `@testing-library/react`; mock `window.nativebridge`, `navigator.geolocation`, `DeviceMotionEvent`, and the axios client. Test-first every task.

## Upstream dependency: location comes from a new bridge topic

The rally *is* a geofence engine — B2 start lock, Task 5 precision radius, Task 12 rest lock, Task 14 trivia and B9 arrival all come from `POST /sessions/me/location` — and the super app grants the WebView no location today. That is being fixed at the source: **`docs/plans/2026-08-10-superapp-location.md`** (`SA-1`..`SA-6`, executed in the `opensuperapp` repo) adds a `location` bridge topic where native owns the sensor and pushes fixes in, which is the only approach that works from a `file://` origin *and* survives the driver switching to Google Maps.

What this plan consumes:

```js
nativebridge.requestLocationUpdates({ accuracy: "high", distanceIntervalM: 10, background: true });
nativebridge.resolveLocationUpdate = (fix) => …;   // fires repeatedly: {lat, lng, accuracy, ts, buffered?}
nativebridge.requestStopLocationUpdates();
```

Three things to hold onto:

- **It is a subscription, not a one-shot.** `resolveLocationUpdate` fires many times; `requestStopLocationUpdates` is the only way to stop it, and failing to call it leaks a battery drain onto a phone whose owner has closed the app.
- **Every fix carries `ts`.** After a spell in the background the host flushes buffered fixes with `buffered: true` and their *original* timestamps. Forward `ts` to the backend (`BE-20`) — the anti-teleport check divides distance by elapsed time, so a replay stamped "now" reads as a teleport and is discarded.
- **`rejectLocationUpdates` reasons** are `permission_denied`, `services_disabled`, `not_declared`, `unavailable`. Surface all four: a phone that silently reports nothing is indistinguishable from a parked car on the organizer's monitor.

`microapp.json` must declare `requiredPermissions: ["location"]` (SA-5) or the host refuses the topic.

Until SA-1..SA-4 ship, MA-5/6/9/10 are built and unit-tested against a mocked `PositionSource` but cannot be verified on a device — so `sensors/position.ts` keeps two implementations behind one interface and picks at runtime.

## Task 2: native bridge + super-app auth + axios client + session store + session service

**Files:** create `src/utils/bridge.ts`, `src/services/auth.ts`, `src/store/session.ts`, `src/services/apiClient.ts`, `src/services/session.ts`, `src/types/session.dto.ts`, `src/types/session.model.ts`; test `src/utils/bridge.test.ts`, `src/services/auth.test.ts`, `src/services/apiClient.test.ts`, `src/services/session.test.ts`.

**Interfaces:**
- `utils/bridge.ts` — one promise per topic over the injected `window.nativebridge`, mirroring `customer-portal/microapp`:
  `requestToken(): Promise<string>`, `requestQr(): Promise<string>`, `secureStore.{set,get,remove}(key, value?)`, `alert(title, message, buttonText)`, `confirm(...)`, `openUrl(config)`, `closeWebView()`, `log(...)`, `isEmbedded(): boolean` (`typeof window.nativebridge !== "undefined"`).
  Each `requestX` installs the matching `window.nativebridge.resolveX` / `rejectX` before posting, and **rejects on a timeout** — an unimplemented topic never answers.
- `services/auth.ts` — `getSuperAppToken(): Promise<string>`: over the bridge when `IS_MICROAPP`, otherwise the Asgardeo browser flow so the app is developable in a desktop browser. This is the *super app's* token, used once, at join.
- `useSessionStore` (zustand): `{ token: string|null, session: SessionModel|null, setJoined(token, session), clear() }`. The team token is persisted through `bridge.secureStore` when embedded (`localStorage` only in browser dev) — a rally token in `localStorage` on a shared phone outlives the event.
- `apiClient` (axios instance, `baseURL: BACKEND_URL`): request interceptor adds `Authorization: Bearer <teamToken>` + `x-user-id-token` + `Content-Type: application/json` when a token exists; response interceptor on 401 → `useSessionStore.getState().clear()` + `location.hash = "#/"`.
- `services/session.ts`: `join(input): Promise<{token, session}>` — POST `SESSIONS_JOIN` with `{vehicleId}` and the **super-app token** in `Authorization` (not the team token; there isn't one yet) — then `getState()`, `ping(lat,lng,accuracy)` (POST `SESSIONS_LOCATION` → `PingResult`), `submit(taskId, payload)`, `finish()`, `getVouchers()`, `raiseAlert(input)`. dto→model mappers `toSession(dto)` (dates via dayjs). Export `session` object of TanStack `queryOptions`/`mutationOptions` (`session.state()`, `session.submit()`).

## Task 3: sensors module (pluggable position source, motion, native QR)

**Files:** create `src/sensors/{position.ts,motion.ts,qr.ts,index.ts}`; test `src/sensors/position.test.ts`, `src/sensors/motion.test.ts`, `src/sensors/qr.test.ts`.

**Interfaces:**
- `position.ts` — **the fix source is behind an interface on purpose**, because the super app cannot supply location yet (see the prerequisite section) and the eventual fix may be a native bridge topic rather than a web API:
  ```ts
  export interface PositionSource {
    watch(cb: (p: { lat: number; lng: number; accuracy: number }) => void): () => void;
  }
  export const bridgePositionSource: PositionSource;   // nativebridge `location` topic — the supported path
  export const webPositionSource: PositionSource;      // navigator.geolocation — fallback only
  export function positionSource(): PositionSource;    // bridge if available, else web
  export function watchPosition(cb): () => void;        // positionSource().watch(cb)
  export function getCurrent(): Promise<{lat,lng,accuracy}>;
  ```
  When neither source can deliver, surface it: a rally phone that silently reports nothing looks identical to a stationary car, and the organizer's monitor cannot tell them apart.
- `motion.ts`: `requestMotionPermission(): Promise<boolean>` (calls `DeviceMotionEvent.requestPermission` when present, else true); `trackMotion(cb): () => void`; `computeEfficiencyIndex(samples): {hardStops, sharpTurns}` (pure — thresholds on accel magnitude / rotation).
