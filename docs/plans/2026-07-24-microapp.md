# Rally Micro App (In-Car PWA) Implementation Plan — Plan 3 of 3

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the in-car participant PWA for WSO2 Motor Rally 2027 — one active phone per vehicle: bind vehicle + crew, geofenced zero-facilitator start, the 15 config-driven tasks (with Web sensor APIs), live score/leaderboard sync, arrival + vouchers, and a vehicle-issue report — against the Go backend (Plan 1).

**Architecture:** React 19 SPA mirroring `customer-portal/microapp` conventions, **except it is a standalone installable PWA, not embedded in the WSO2 Open Super App**. There is no native bridge: a `sensors/` module wraps Web APIs (Geolocation, DeviceMotion, camera/BarcodeDetector, QR, wakeLock) and `services/session.ts` binds a vehicle to get a backend team token in place of the native `getToken()`. Retains: `axios` client with interceptors, `zustand` store, `HashRouter`, `formik`+`yup`, the `.dto.ts`/`.model.ts` split with `toX(dto)` mappers, services exporting TanStack `queryOptions`/`mutationOptions`, build-time env, MUI + Oxygen theme.

**Tech Stack:** React 19.2 · Vite 7 · TypeScript 5 · `@mui/material` 7 + `@wso2/oxygen-ui` · `@tanstack/react-query` 5 · `react-router-dom` 7 (`HashRouter`) · `axios` · `zustand` · `formik` + `yup` · `dayjs` · `@zxing/browser` (barcode fallback) · `react-leaflet` · `vite-plugin-pwa` · `vite-tsconfig-paths` · `vitest` + `@testing-library/react` · prettier · npm.

## Global Constraints

- **Mirror `customer-portal/microapp` conventions** (axios interceptor client, zustand store, `HashRouter`, dto/model split, services with TanStack options, MUI+Oxygen theme, prettier `printWidth 120`, `vite-tsconfig-paths`) — but **replace the native `microapp-bridge` and `services/auth.ts`** with `sensors/` + `services/session.ts` (team-token bind). No `window.nativebridge`, no `ReactNativeWebView`.
- **Build-time env, not runtime.** `config/endpoints.ts` reads `import.meta.env.RALLY_BACKEND_URL` and **throws** if undefined. `.env.example` documents `RALLY_BACKEND_URL`. `vite.config.ts` `envPrefix:["RALLY_"]`, `base:"./"` (relative asset paths for arbitrary mount), PWA plugin.
- **Auth:** the axios client sends `Authorization: Bearer <teamToken>` + `x-user-id-token: <teamToken>`; on 401 it clears the session store and routes to `#/` (re-bind), never silently retries forever.
- **Error body:** backend returns `{"message": ...}`; surface via a snackbar context; never swallow.
- **dto/model split:** wire shapes in `src/types/<domain>.dto.ts` (string dates, nullable), UI models in `src/types/<domain>.model.ts` (typed, `Date` via dayjs); services hold `toX(dto): Model` mappers.
- **License header:** Apache-2.0 (year 2026) on every `.ts`/`.tsx`.
- **iOS reality:** `BarcodeDetector` and `DeviceMotionEvent.requestPermission` differ on iOS Safari — `sensors/` must feature-detect and fall back (`@zxing/browser` for barcode; a gesture-triggered permission for motion; manual entry always available). BLE tasks use QR/geofence, never Web Bluetooth.
- **TDD:** `vitest` + `@testing-library/react`; mock `navigator.geolocation`, `DeviceMotionEvent`, and the axios client. Test-first every task.
